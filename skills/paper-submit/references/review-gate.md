# 提交前审阅

终点动作之前，先自己回读核对，再把审阅包交给用户。用户明确批准某一篇，才执行那一篇的终点动作。

## 1. 自查：以系统生成的结果为准

拿系统生成的 PDF 或汇总页，与投稿包清单逐项核对。新投稿系统在提交前不生成 PDF 时，把实际上传的文件转成 PDF（`soffice --headless --convert-to pdf`），再加上系统里填的元数据。

| 项目 | 看什么 | 常见问题 |
|---|---|---|
| 作者 | 顺序、有无重复、通讯标记 | 报错重试后，系统里留下两条同名作者 |
| 邮箱 | 和邮箱方案表一致 | 作者页写一个邮箱，系统里填的是另一个 |
| 摘要、题目 | 结尾完整，没有 LaTeX 残留 | 带 `\%` 的摘要被截断在反斜杠处 |
| 文件 | 每个文件的类型、份数、版本对不对 | |
| 基金、分类、数据声明 | 和稿件一致 | 基金名有错别字 |
| 匿名性（双盲刊） | 匿名稿里没有姓名、单位、邮箱、带用户名的仓库链接 | |
| AI 相关 | 按 form-answers.md 的检索要求，与作者决定的写法一致 | |
| 投稿信 | 是当前版本，邮箱和作者页一致 | |
| 引用与交叉引用 | 系统编译的 PDF 里搜 `(?)`、`??`、`[?]`，应为 0；参考文献表不为空 | 系统不跑 BibTeX，引文全成了 `(?)`，前两轮审阅都没发现 |

## 2. 审阅包

一篇一节，写成一份报告放在论文项目里，回复里给报告和各篇 PDF 的路径（或你们内部能预览的链接）；稿件投出前不发公网。每篇包括：
- 作者表，以系统里存的为准：顺序、姓名、邮箱、单位、通讯标记、谁是投稿人。
- 题目和摘要的原文（从系统汇总页或系统 PDF 里取，不从投稿包抄）。
- 系统生成的 PDF。新系统没有 PDF 时，附上传文件转出来的 PDF。
- 和用户上次看过的版本相比，改了什么。
- 声明清单，逐项写投稿文件里有没有、原文怎么写：
  - AI 使用相关；
  - 局限和边界类表述；
  - 数据与代码可用性；
  - 利益冲突、基金、伦理；
  - 系统里每道是非题的原文和所选项。
- 邮箱替代、借用的情况。
- 需要用户决定的事。一次列完，按人话写。

用户要审边界类表述时，把相关段落原文逐段列出来，每段标「保留」或「可改写」。改写只能用稿件和冻结结果里已有的事实，不新增结论，不改变结论的强弱。

## 3. 批准与提交

- 批准要具体到哪几篇，而且是在用户看过上面这份审阅包之后。「先推进」「都弄好」「全权交给你」「弄完就投」都不算批准，主代理、其他代理或子代理转达的也不算。用户说回来再看，就一直等着。
- 提交前确认通讯作者的邮箱能读，见 preflight.md 第 3 节。
- 提交时只做终点动作这一步。做完 snapshot 留证据，再查回执邮件。
- 提交后提醒用户处理作者自己要做的事（例如按期刊政策另行向编辑部说明的事项）。
- 提交后回读系统的确认信：抬头称呼、用户名、通讯作者是不是预定的人。不对就马上告诉用户，起草给编辑部的更正信。

## 4. 合著者确认（Elsevier 系常见）

提交后，系统会给每位合著者发「verify your contribution / confirm co-authorship」邮件。

- 有的刊写明合著者都确认之前不进入编辑流程，60 天内没确认可能被撤稿。以该刊确认信的原文为准。
- 这封信等于合著者授权通讯作者签出版协议，属于以作者名义的声明。
- 做法：列出每位合著者的确认信落在哪个邮箱、服务器能不能读，交给用户决定由谁去点；用户明确授权代点后才点，且只点能读的邮箱。
- 代点时用干净的、未登录的浏览器会话（新的投稿人 ID），免得确认挂到别人账号上。有的刊不用登录，点「Submit to Publication」即可；有的刊要先登录该合著者自己的账号，没账号就在确认页点 Register Now，注册完成即确认。不要先试错登录，试错后链接可能失效。
- 查谁还没确认：用投稿人账号打开该稿的 Author Status 页，看每位合著者的「Confirmed?」列（Yes / No Response）。
  - 有的刊在 Submissions Being Processed 那一行有「Author Status」链接；
  - 没有链接的刊，页面也能直接打开：`https://www.editorialmanager.com/<刊缩写>/ContributingAuthorStatus.aspx?docID=<docID>&msid=<msid>&revision=0`，两个参数取自同一行 View Submission 的 `viewAuthorPDFs(docID, '稿号', 0, 'msid')`。
- 这是唯一可靠的口径。确认链接显示「not currently available」可能是已确认，也可能是失效；作者本人说「点过了」也要以这一页为准。常见的没点成：只打开了链接，没按页面上的确认按钮；或点的是同题旧稿号的确认信。
- 没查这一页之前，不要告诉用户「某人要本人去点」或「已经确认」。
- 同一页有「Send Letters」，可给所有未确认的合著者重发确认信。这是对外发信，先问用户。
- 交给用户的提醒清单只列确实没确认、且邮箱我们读不到的人，写明会不会卡审稿。
