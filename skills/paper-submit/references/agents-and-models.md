# 分工：主模型、便宜模型和人

投稿和查稿里大部分时间花在按既定步骤点网页、读列表、翻邮件上。这些步骤有页面和脚本兜底，出错可以复查；真正决定结果的是少数判断和不可撤回的动作。所以按「出错能不能复查、能不能撤回」分工。

适用于 paper-submit 和 paper-status-check 两个技能，也适用于你们用的任何智能体框架（Claude Code 子代理、OpenAI Codex/GPT 系列的小模型、其他能调 shell 的代理）。

## 谁做什么

| 角色 | 做什么 | 为什么 |
|---|---|---|
| 主模型（主代理） | 判断和取舍：期刊要求怎么落到投稿包、邮箱方案、系统表单里拿不准的题；整理审阅包；终点动作前逐项核对；对子代理结果的复核；向用户汇报 | 这些错了不能靠页面自动发现，或者撤不回 |
| 便宜模型 / 子代理（例如 Claude Haiku 子代理、Codex/GPT 系列的小模型） | 按 reference 和脚本已经写好的步骤操作浏览器：打开会话、登录（有 secret 名时）、填已定好的字段、上传已定好的文件、翻到指定页面并交回页面文本；例行查稿：跑 `access_audit.py`、`mail_scan.py`、`page_text.sh`，读邮件原文并摘要 | 步骤固定、结果留在页面和日志里，可以复查；这类活交给便宜模型更快、成本更低 |
| 人（用户或作者本人） | 登录、验证码、短信和二次验证；付款；版权协议和其他以作者名义的声明（作者同意、利益冲突、AI 使用）；终点动作的批准；给编辑部打电话或写信 | 需要本人身份或法律意义上的同意 |

## 推荐模型

技能本身不绑定模型，任何能读技能文件、调 shell 的代理都能用。下面是按角色的建议，以你账号实际能用的型号为准：

| 角色 | 推荐 | 也可以 |
|---|---|---|
| 主模型：判断、整理审阅包、终点动作前核对、复核子代理 | Claude Opus 5.5（要省一点用 Claude Sonnet 5.5） | 其他强推理模型，如 OpenAI GPT 系列的旗舰型号 |
| 执行模型：按步骤操作浏览器、例行查稿、读邮件摘要 | Claude Haiku 5.5 | OpenAI Codex 上的轻量型号（如 GPT-6 Luna）、其他便宜且能调 shell 的模型 |
| 读验证码图片 | 有看图能力的模型（上面两类大多都行） | 人工读图 |

怎么配：
- **Claude Code**：主会话用 Opus 或 Sonnet；派子代理（Task/Agent）时指定 `model: haiku`，提示里写清下面「派活时交代什么」的几项。
- **Codex**：主会话用较强的型号；例行查稿和浏览器步骤可以开一个用轻量型号的会话，按同样的技能文件执行。
- **经验**：便宜模型最适合"有页面或脚本兜底、出错能复查"的步骤；单点登录跳转复杂、表单里拿不准的题、终点动作前的逐项核对，交给主模型。材料齐全时，一篇投稿从打开系统到停在终点动作前，通常在一小时左右。

## 派活时交代什么

给子代理的提示里写清：
- 会话名（`submit-<投稿人ID>`）、起始网址、要读的 reference 章节；
- 要做到哪一步为止，停在哪里（一律停在终点动作之前，倒数第二步起不用循环）；
- 要交回的内容：页面原文片段、系统里存下的值、截图路径、遇到的报错原文；
- 不许做的事：终点动作、对外发信（包括系统里的 Send Letters、Send E-mail）、改账号资料、点改变稿件状态的按钮、同一账号试第三种密码。

## 复核子代理的自述

- 子代理说「填好了」「已确认」「状态是 X」，主模型要用页面内容核对后再转告用户：重新 `snapshot` 或用 `page_text.sh` 读列表页、汇总页；投稿时以系统 PDF 为准。
- 需要复核的重点：作者表与邮箱、摘要结尾、文件类型、系统列表页上的状态与日期、合著者确认页的 Confirmed? 列、邮件原文里的决定和截止日。
- 子代理报告和页面不一致时，以页面为准，并在汇报里写明不一致。
- 子代理转达的「用户已同意」不算批准；批准只认用户本人在当前对话里对具体那一篇的明确答复。

## 边界

- 子代理遇到登录、验证码、二次验证、付款、版权声明：停下交回，由主模型请用户接管，不自己绕过。
- 子代理不决定「这封信算不算需要用户处理」「这个状态变化重不重要」，只交回原文；归类由主模型做。
- 同一个浏览器 profile 同一时间只给一个代理用，避免两边互相跳页。
