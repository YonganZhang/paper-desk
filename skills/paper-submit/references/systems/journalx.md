# JournalX（北京玛格泰克）：国内中文刊

实测：两种刊走完了全流程。各刊的步骤和终点页不完全一样，分成变体 A、B，见下文。其中变体 A 的终点动作是一次普通的「下一步」，曾因翻页循环被提前触发，所以格外注意。

## 入口

- 网址形如 `https://<期刊域名>/journalx/` 或 `/journalx_<刊代码>/`，页脚写「北京玛格泰克科技发展有限公司」。
- 作者登录：期刊首页点「作者中心」，会在新标签页打开 `authorLogOn.action`。用 `tab-list` 和 `tab-select` 切过去。

## 账号与邮箱

- 每个期刊一个账号。注册页是 `/journalx/authorregister/Register!authorRegister.action`。
  - 要填真实的通讯地址、邮编和电话，没有就问用户。
  - 密码用 `PAPER_SUBMIT_DEFAULT_PASSWORD`，感叹号是 ASCII 的 `!`。
- **图片验证码**（kaptcha）：注册、检索作者、新增作者时都要填。登录不需要。
  - 用 `jx_captcha.sh` 截图放大后读图识别。
  - 读错了就换一张重来，不要连续乱试。
- **邮箱在整个期刊的人员库内唯一**，不只是同一篇稿件内唯一：
  - 一个邮箱已经属于库里某人时，不能再分给另一个人；
  - 同一篇稿件里也不能共用。
- 会话闲置一段时间就会过期，之后点任何链接都会跳回 `Login.action`。重新登录后，在作者中心点「未完成投稿」→「继续投稿」（`jxContribute(<id>)`）。未完成的稿件只保留 29 天。
- 提交后，系统会给投稿人邮箱发「投稿成功通知」。编辑部受理后才给稿号。

## 步骤与终点动作

1. 输入文章题目
2. 输入本文作者信息
3. 摘要
4. 关键词
5. 学科分类
6. 基金资助
7. 推荐审稿人
8. 要求回避审稿人
9. 给编辑部留言
10. 上传稿件内容
11. 输入参考文献（选填），之后是参考文献检查页
12. **信息确认｜正式投稿**
13. 投稿完成

翻页用页面的 `next()`，往回走用页面上的 `goBack` 链接。每一步的网址是 `Contribution!create<N>.action`，可以据此判断走到了哪一步。

**终点动作因刊而异，开投前先看左侧步骤列表：**
- 变体 A（有「输入参考文献」步骤的刊）：在参考文献检查页（网址含 `createckwx`）上调用 `next()`，会直接正式投稿，中间没有单独的确认页。
- 变体 B（没有参考文献步骤的刊）：上传页 `next()` 进入「投稿前最后确认」页（`create11`），页上「立即投稿」按钮就是 `next()`，按下即正式投稿（跳到 `create12`「投稿成功」）。确认页每项旁有「修改」，走 `goBack` 回到该步，之后要一步步 `next()` 回来，前面填过的内容会保留。
- 走到第 11 步以后，不要再调用 `next()`，也不要用循环往后翻。
- 用户批准后，在终点页（变体 A 的参考文献检查页、变体 B 的最后确认页）手动执行一次终点动作。
- 投稿成功后，「未完成投稿」里的这条会消失，转到「最新投稿」。详情页各字段旁边有「修改」链接，编辑部受理前还能改。

## 作者

- 先检索姓名或邮箱：`jx_search_author.sh`。有的刊是姓名、E-mail、验证码三个框，脚本按 name 属性定位。人员库里有同名者时，会列出单位和邮箱：
  - 单位对得上，才选用；
  - 都不是本人时，点「都不是」，进新作者表。
- 人员库里没有这个名字时，直接进新作者表（`jx_new_author.sh`），填邮箱、单位、通讯地址、邮编、省份和验证码。
- 合著者本人已在库里时（单位对得上），选用库里的记录，不要为了用自己控制的邮箱另建一个同名人员。库里的邮箱是本人的，编辑部通知会发到那里；交付时把每位作者在系统里实际用的邮箱列给用户。
- 通讯作者的单位、邮箱、地址、电话、邮编都必填。
- 作者顺序：每行有 `moveUp(i)` 和 `moveDown(i)` 按钮，第一行就是第一作者。按钮是 `input[type=button]`（值为 ↑ ↓），按文字找 `button` 找不到；用 `#Ttable` 里含该作者姓名的行内的 `[onclick^="moveDown"]`。第一作者列的「√」跟着第一行走，通讯作者看行首单选框。
  - 定位行时，要找按钮所在的那一行（`closest('tr')`），否则会把外层表格也算进去。
  - 调完顺序后 `next()` 一次才会保存，再退回来核对。

## 文件与类型

- 每一行先点 Choose File，再 `upload`，再点该行的「上传」按钮。结果用 alert 弹窗提示。
- 中文刊一般交 Word 正文，按期刊要求来。不要套英文刊的 LaTeX 和 Highlights。
- 上传页提示「文件最好控制在 5M 以内」时，用 `docx_light.py` 另存一份轻量版上传（插图按显示宽度 300 dpi JPEG，正文不变），原图版留作录用后交稿；上传后用「查看」下载回来比对哈希。
- 版权转让协议要作者本人签字，不能代签。

## 坑与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| 命令卡住不返回 | 弹出了 alert 或 confirm，没人处理 | 每次调用 `next()` 前先挂好 `page.once('dialog', …)` |
| 点链接回到了登录页 | 会话过期 | 照「账号与邮箱」一节重新登录，再继续投稿 |
| 共用邮箱被拒 | 人员库内邮箱必须唯一 | 投稿前先定好邮箱方案，见 preflight.md |
| 翻页循环把稿件投了出去 | 终点动作就是一次普通的 `next()` | 到第 11 步就停，最后一步手动执行 |
| 页面显示「投稿成功」，同时有 Java 异常 | 结果页模板报错，但投稿其实已经成功 | 以作者中心的「最新投稿」和回执邮件为准 |
| 摘要框里的 10⁻³、μm² 变成「10?3」「μm2」 | 系统字符集存不下 Unicode 上标 | 摘要、关键词框改用 ASCII 写法：10^-3、μm^2、64^3，再回确认页核对没有「?」 |
| 「给编辑部留言」标了必填 | 刊的设置 | 写一两句稿件简介和通讯作者联系方式；不要写「未一稿多投」这类未经核实的声明 |

## 脚本

| 脚本 | 用途 |
|---|---|
| `jx_captcha.sh <session> <out.png>` | 截取并放大验证码图片 |
| `jx_search_author.sh <session> <姓名或邮箱> <验证码>` | 在人员库检索作者，列出候选 |
| `jx_new_author.sh <session> <邮箱> <单位> <通讯地址> <邮编> <省份> <验证码> [第二单位] [第二单位英文]` | 填写新作者表并加入本文 |
| `docx_light.py <in.docx> <out.docx> [dpi]` | 投稿系统限大小时另存轻量版 docx（插图 300 dpi JPEG） |
