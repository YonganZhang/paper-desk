# 多模型模拟审稿（可选）

交付前的可选一步：几个审稿者拿到同一份冻结材料，各自假扮原审稿人，判断这次返修能不能过，并指出致命问题。审稿者可以是任何可用的模型或子代理（不同厂商的模型、同一模型的独立子代理都行），关键是**各自独立审、互相看不到对方结果，再由主模型汇总核实**。

试审结果只供作者决定是否继续修改，不能当作期刊的真实决定，也不能用"多数通过"证明稿件没有问题。

## 前提

- 质检清单已经过完。试审用来发现主模型没看出的问题，不替代质检。
- 材料已冻结：试审期间不再改稿件和回复信。试审之后又改了的，在汇总里写明试审针对的是哪一版（manifest 里有各文件的哈希）；改动较大时重新试审。
- **保密**：把未发表稿件发给外部模型服务之前先问作者；稿件有保密约定（合作方数据、专利、期刊保密要求）时，只用本地或作者同意的服务。

## 1. 打包

```bash
python3 -I scripts/mock_review.py packet \
  --comments <决定信.txt> --old <上一轮投稿稿> --new <标红稿.docx 或 main.tex> \
  --response response.md --journal "<期刊全名>" --out <返修工作目录>/mock_review
```

- `--new` 优先给标红稿：Word 标红稿的红字会被转成 `{+ … +}`；LaTeX 稿给 `main.tex`，`\rev{…}` 原样保留，`\input`/`\include` 的子文件按 LaTeX 的规则展开（注释里的不展开），审稿者能看出改了什么。LaTeX 稿另用 `--extra out/main_marked.pdf` 附上编译好的标红 PDF，供能读文件的审稿者看图表和公式。
- 原始文件会复制到 `originals/`，能打开文件的审稿者可以查看图、表和公式；只能读文本的审稿者，凡是依赖图片的判断标 cannot judge。
- `--old` 应当提供。拿不到时包会被标为"材料不全"：试审仍可做，但只能算有限试审，汇总里要写明。
- 补充材料用 `--extra` 附上。
- 每个包有一个 PACKET_ID（材料文字和 `originals/` 原件的哈希），图片或公式变了 ID 也会变。同一目录已有报告时脚本拒绝重建；确需重建用 `--force`，旧报告会移到 `reports/_history/`。
- 打包后看一眼输出的 warnings：稿件只抽出几千字通常是转换失败。
- 依赖：Python 标准库；输入有 PDF 时需要 `pdftotext`。脚本本身不调用任何模型、不联网。

## 2. 各自独立试审

每个审稿者用同一份 `prompt.md`，互相看不到对方的结果，把报告写到 `mock_review/reports/<名字>.md`。

- **能读文件的代理或子代理**：任务里写清三点——读取 `<packet>/prompt.md` 并按其要求审稿，材料都在 `<packet>/` 下；把完整报告写到 `<packet>/reports/<名字>.md`；除此之外不修改任何文件。子代理不带当前会话的上下文，只给这段任务。
- **只能对话的模型（网页或 API）**：把 `prompt.md` 和包里全部 `.txt` 文件内容一起发过去，告诉它不能打开原件、依赖图片的判断标 cannot judge；把回答原样存成 `reports/<名字>.md`。
- 建议 2–4 个审稿者，能并行就并行。某一家失败时记录失败原因（额度、网络、超时），不无限重试；汇总里写明缺了哪家。

每份报告收回后先校验：

```bash
python3 -I scripts/mock_review.py verify <packet>/reports/<名字>.md <packet> [--expect-comments N]
```

`verify` 会重算包的哈希，并检查报告：PACKET_ID 一致；VERDICT、总体建议和置信度是规定的取值；各必需章节非空、表格有数据行；VERDICT 与总体建议和 critical 问题一致；加 `--expect-comments N` 时逐条核对表至少有 N 行。不通过的报告不计入汇总（可以让该审稿者按格式重写一次）。

## 3. 汇总（交给用户，中文）

主模型读完全部报告后写 `mock_review/summary.md`：

1. **结论表**：每家的 VERDICT（PASS / FAIL / INSUFFICIENT_MATERIALS）、总体建议（Accept / Minor / Major / Reject）和置信度。PASS 表示该审稿者认为这一版大概率能过（Accept 或 Minor，且没有 critical 级问题）；包被标为"材料不全"时在表头写明。
2. **共同问题**：两家及以上都提到的问题。
3. **逐条核实**：每个致命问题由主模型回到稿件和回复信核实，标"成立""不成立（理由）"或"无法判断（缺什么）"。审稿者说的页码、引文和数字都要核对原文后才能引用。
4. **建议**：哪些成立的问题需要改回复信，哪些需要改正文，哪些可以不改；最终是否继续修改由作者决定。

提示词里的审稿任务对各家完全相同，便于比较结论；需要侧重某个方面（如数值核对）时，在任务里加一句关注点，各家同步加。
