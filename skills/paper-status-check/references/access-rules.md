# 查询路径：怎样才算"查得到"

## 三个身份

一篇稿件涉及三个身份，先分开写清：

| 身份 | 在哪看 | 要回答的问题 |
|---|---|---|
| 投稿人 | 台账本轮的账号字段；`$PAPER_SUBMIT_HOME/accounts.json` 里的投稿人 profile；投稿回执邮件发给了谁 | 稿件挂在哪个系统、哪个账号下，服务器能不能登录 |
| 系统通讯作者 | 系统 PDF 首页的 Corresponding Author；回执和决定信的收件人 | 期刊来信先发给谁，那个邮箱服务器能不能读 |
| 第一作者 | 台账作者字段的第 1 位 | 一般只收抄送。抄送不一定每封都有，不能当作唯一来源 |

三个身份可能是同一个人，也可能是两三个人。多数系统只有投稿人账号的列表页能看到稿件；共同作者账号看不到，除非实测证明能看到。

**以回执为准，不以记忆为准。**

- 回执和决定信的抬头（例如 "Dear Dr. EXAMPLE"）和收件人，就是系统里的通讯作者兼投稿人。和用户或台账记的不一样时，以回执为准，再把差异告诉用户。
- 再核对系统 PDF 首页的 Corresponding Author 是不是本篇作者表里的人。
- 系统通讯由投稿账号的档案名决定。多个人共用一个邮箱时，可能出现档案名是 A、稿件作者表里却没有 A 的情况。

## 判定

- **可查（绿）**：至少一条登录路径已经实测，能在列表页看到本稿号；投稿人或系统通讯作者的邮箱至少有一个服务器能读（邮箱登记 `mailboxes.json` 里该地址 `readable: true`，且 `author_links` 关联到本篇）；实测在 60 天以内。
- **待实测（黄）**：路径和邮箱都登记了，但还没有登录看到过；或者账号只是按同一系统推测出来的，没有按编号登记。
- **查不到（红）**：没有任何登录路径；或者投稿人和系统通讯作者的邮箱都读不到；或者本篇作者邮箱根本没登记。红色要当轮报告用户。

## 红黄怎么补

按顺序做，每步都留证据：

1. **找回执。** 在所有能读的邮箱里，按稿号、题目关键词和投稿日期搜回执、作者确认信和决定信。
   - 收件人就是系统通讯作者的邮箱。
   - 信里的系统链接说明稿件在哪个系统。
2. **定账号。** 从回执的收件人、台账本轮账号、`accounts.json` 里定投稿人账号。
   - 没有密码时，先用该系统的找回密码功能，前提是找回邮件能发到服务器读得到的邮箱。
   - 找回邮件发不到能读的邮箱时，报给用户：写明该找谁、要什么（账号持有人的名字、邮箱、要做的动作）。
3. **登录实测。** 用投稿人 profile 打开浏览器，进列表页。
   - 看到稿号后，记一条 `[可查性已验证]` 跟进事件。
   - 账号还没按编号登记的，在 `accounts.json` 该条的 `paper` 字段补上编号（空格分隔）。
4. **补邮箱登记。** 确认后的作者和邮箱，在 `mailboxes.json` 该地址的 `author_links` 里加上这篇论文；再跑 `access_audit.py` 复核。
   - 系统通讯作者的邮箱读不到时，看能否接入：授权码存进你们的凭证库，配置里写 `password_env` 或 `password_cmd`，`scripts/mailboxes.py check <地址>` 通过后标 `readable: true`。
   - 不能接入的，告诉用户：这篇论文的来信只能由谁转发。
5. **还是查不到：** 写明试过哪些路径、卡在哪里，交给用户。不能把"没查到"写成"没有变化"。

## 什么情况下必须问用户

- 账号属于学生或合作者本人，要对方配合登录或转发邮件。
- 需要验证码、短信、本人登录确认。
- 系统里的信息和台账冲突，例如稿号、作者、通讯不一致。
